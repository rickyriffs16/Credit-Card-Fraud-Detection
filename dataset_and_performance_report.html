1 Dataset Characteristics & Schema Breakdown

The system was trained and evaluated using the standard European credit card fraud benchmark dataset, containing real transactional activity over a 48-hour recording window:

Dataset Parameter Observed Measurement / Value Significance & Preprocessing Role
Total Instances 284,807 transactions Comprehensive scale representing real banking transaction volume.
Genuine Transactions 284,315 instances (99.828%) Majority class representing normal everyday consumer behavior.
Fraudulent Transactions 492 instances (0.172%) Extreme class imbalance (≈1 fraud per 578 legitimate swipes).
Feature Dimensions 30 numerical input features + 1 target Time, Amount, V1–V28 (PCA coordinates), and binary Class.
PCA Anonymization Features V1 through V28 Scrambled banking variables (location, device, frequency) protecting customer PII.
Scaling Applied StandardScaler (Z-score normalization) Applied to Time and Amount strictly fitted on training distribution.
2 Data Partitioning & SMOTE Imbalance Strategy
Stratified 80/20 Hold-Out Split

• Training Set: 227,845 records (contains 394 fraud cases).
• Test Set (Untouched): 56,962 records (contains 98 fraud cases).
• Integrity Rule: Stratification preserves identical 0.172% fraud proportion with zero test-set leakage.

SMOTE Training Oversampling

• Pre-SMOTE Training: 227,451 genuine vs. 394 fraud.
• Post-SMOTE Training: 227,451 genuine vs. 227,451 synthetic fraud.
• Impact: Balanced 454,902 training samples forced algorithms to learn robust decision boundaries without copying test points.

4 Confusion Matrix Deep Dive & Error Analysis

Confusion matrix breakdown for Random Forest on 56,962 hold-out test transactions (containing 98 actual frauds):

True Positives (TP = 83 Transactions)

Successfully detected 83 out of 98 real fraudulent attempts, yielding an 84.69% fraud recall rate on unseen data.

True Negatives (TN = 56,824 Transactions)

Accurately verified 56,824 genuine transactions with a 99.93% specificity rate, ensuring legitimate purchases pass through.

False Positives (FP = 40 Transactions)

Only 40 legitimate transactions incorrectly flagged (0.07% False Alarm Rate). Outperforms Logistic Regression by over 1,400 fewer customer disruptions.

False Negatives (FN = 15 Transactions)

15 fraud attempts evaded the primary classifier. These instances are captured through secondary threshold rules and velocity monitoring.

6 Latency, Throughput & Operational Verdict
Production Speed & Latency

• Single Transaction Scoring: ~38 ms (well under the 100ms payment gateway SLA).
• Batch CSV Throughput: 1,000 transactions scored in 1.4 seconds (~1.4 ms/row).
• Memory Footprint: Pre-loaded model pipeline consumes <150MB RAM.

Enterprise Deployment Verdict

Random Forest is the clear winner for commercial deployment. While Logistic Regression achieved higher recall (91.8%), its 1,458 false alarms would disrupt customer loyalty. Random Forest delivers an optimal balance with **84.7% Recall, 67.5% Precision, and only 40 false alarms**.
